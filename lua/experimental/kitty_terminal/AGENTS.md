# Lua 自管终端辅助模块

入口为 `init.lua`，浮动终端也会按需加载。Lua 负责原始 PTY 和协议处理，Neovim
内部终端负责显示及普通交互；需要松键事件的程序按需使用宿主输入桥。

## 模块职责

- `parser.lua`：增量解析 UTF-8、ESC/CSI 和 OSC/APC/DCS
  帧。保留字符串载荷字节及终止符；超限显式报告，不静默截断。默认单包上限 16MB。
- `screen.lua`：维护单元格网格、稳定行 ID、历史、SGR、光标/编辑操作、滚动边界和备用屏幕。`render()`
  返回文本行、按字节索引的高亮范围，以及行 ID 到缓冲区行号的映射。
- `protocol.lua`：处理本地查询、模式协商、调色板/剪贴板行为和私有字符串分发。原生输入支持键盘消歧、全键报告和关联文本（掩码
  25）；真实宿主输入桥就绪后增加按下、重复和松开事件（掩码 27）。不宣称支持替代键标志。OSC52
  读取须显式授权。
- `graphics.lua`：管理宿主图片 ID
  命名空间、图片尺寸、缓冲后的原子分块上传、本地能力应答、放置生命周期、逐视图像素裁剪和宿主响应路由。读取文件元数据前以非阻塞方式打开并验证同一描述符的文件类型，防止
  FIFO/设备路径阻塞界面。默认上传缓冲上限 64MB，关闭时释放所属宿主资源。
- `input.lua`、`render.lua`、`tty.lua`：分别负责原生 `on_input`
  字节编码/粘贴/鼠标、内部终端通道显示及图形绘制、Linux 单元格和像素窗口尺寸 ioctl。
- `colors/init.lua`：按 `KITTY_LISTEN_ON` 与 `KITTY_WINDOW_ID` 读取外层 Kitty
  当前窗口的实时前景、背景、光标和 256 色调色板。浮动终端每次打开时读取，查询等待上限
  500ms；缺少远控条件或查询失败时保留 Neovim 默认配色，查询错误显示在 `KittyLuaTermStatus` 的
  `color_error` 字段。

- `host_input/`：程序请求键盘事件类型时，用本地 Kitty
  远控创建隐藏输入窗口，按实际协商标志编码并经私有 Unix socket 回传。Neovim TUI
  会丢弃释放事件，因此不能仅修改能力掩码。需要
  `kitten`、`python3`、`KITTY_LISTEN_ON`、`KITTY_WINDOW_ID`，不支持经过 tmux
  的输入桥；缺少条件时保留原生能力并在 `KittyLuaTermStatus.keyboard_error` 明确报告。

## 集成约定

控制器管理原始 `jobstart({pty=true})` 回调，并另建 `nvim_open_term` 通道。普通 Lua
屏幕操作镜像到内部通道，不直接修改终端缓冲区文本；嵌套屏幕调用不能重复镜像。任务回调以列表边界表示真实换行，以字符串内换行表示
NUL；应先还原各段，再拼接。引导 shell 发出私有就绪 DCS，等候 Lua
回传一行，像素尺寸安装完成后才执行真正命令。

图形能力探测必须在 DA 响应之前本地回复：icat 收到 DA 即结束探测，terminal-browser
也有较短的图形查询期限。不得把子进程键盘/备用屏幕模式转发到 Neovim 外层
TTY。普通光标、鼠标、备用屏幕模式仅镜像到内部视图。Kitty 键盘协商保留在
Lua，原生输入适配器将基础编码转换为子程序协商的格式。像素鼠标模式同样在 Lua 中处理，将原生 SGR
单元格坐标转换成子程序像素坐标。只有具有宿主效果的字符串协议通过 `nvim_ui_send` 委托给外层终端。

`render.views` 的宿主坐标指向窗口内容区：`getwininfo`
返回浮窗外框位置，必须加上顶部、左侧边框占用的单元格，再计入文字侧栏偏移；宽高保持内容区尺寸。

`open({colors=...})` 的配色同时用于局部窗口高亮、内部终端初始 ANSI 调色板、SGR 真彩色转换与 OSC
4/10/11/12
查询应答。颜色只作用于该窗口，不修改全局主题或宿主配色；已打开的会话保留打开时的颜色快照。

跨会话的完整图形上传必须原子提交。续包没有独立图片 ID，可能仅含 `m`/`q`（动画帧还可含
`a=f`），不要添加放置元数据。先刷新文字单元格，再绘制图片。图片绑定稳定网格行
ID，而非当前焦点窗口。部分可见图片裁剪时保留原始源尺寸。

即使没有新子进程输出，原生界面重绘（包括进入/离开终端模式）也可能擦除宿主图片。装饰提供器在 Neovim
刷新后调度仅图形重绘，不能写终端通道或递归触发重绘。原点模式下光标同步和 CPR
使用相对滚动边界的行号。原生 ESC、Alt+[、Alt+O 歧义前缀采用 30ms 输入超时。宿主输入只在当前会话的
Terminal-mode 捕获，`Ctrl-\\ Ctrl-N`
释放捕获；失焦、退出终端模式及输入桥异常断开时释放按住的键。关闭会话时清理
socket、子进程与该会话拥有的隐藏窗口，不修改 Kitty 的全局映射或配置。内部终端不能可靠应用 OSC4
调色板变更，因此按 Lua 调色板将 SGR 转为真彩色。

浏览器刷新前不能删除可见放置。复用每视图的放置 ID，用 `p=` 原位替换。重新上传同一图片 ID
也会使宿主放置失效：完整上传、显式删除和替换放置须等待同一次显示提交，以同步刷新模式 2026
包裹，单次写入宿主。删除先于有效图片上传；已删除且不要求应答的待上传数据可丢弃，要求应答的上传必须完成并立即释放像素，保留应答路由直到宿主确认。每次上传独立保存
q/p 等应答元数据；`q=1`
仅报告错误，不能提前把放置成功当作上传完成通知，以免客户端过早释放共享内存。关闭时仍立即清理资源。动画验收采样
30 个合成器画面，要求动画像素确实变化、稳定页面像素不露出 Neovim 背景，且不发生多余放置删除。

不得把虚拟/相对图片放置静默转换为普通放置。不支持的语义须保留显式错误和 TODO。本实验拒绝
`U=1`，相对放置语义和 OSC66 尺寸仍不完整。测试与运行限制见 `../AGENTS.md`。

图片只指定 `c` 或 `r`
时，另一轴按源图裁剪区域的像素比例计算；两轴都指定时按边界等比例容纳。裁剪使用实际缩放像素尺寸，完整可见的单轴放置保留宿主自动计算，不能把取整后的单元格高宽强制传回导致拉伸。真实键盘传输回归为
`python3 -u -B tests/unit/kitty_keyboard_host.py`，通过 Kitty
自身编码并注入本测试的隐藏窗口，不抢用户焦点；多键事件、退出
Terminal-mode、双会话切换、失焦和资源清理均包含在 `make test-host` 中。
