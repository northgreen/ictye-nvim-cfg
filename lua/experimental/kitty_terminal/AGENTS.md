# Lua 自管终端辅助模块

手动启用入口为 `init.lua`。Lua 负责原始 PTY 和协议处理，真正的 Neovim 内部终端负责显示及原生交互。

## 模块职责

- `parser.lua`：增量解析 UTF-8、ESC/CSI 和 OSC/APC/DCS 帧。保留字符串载荷字节及终止符；超限显式报告，不静默截断。默认单包上限 16MB。
- `screen.lua`：维护单元格网格、稳定行 ID、历史、SGR、光标/编辑操作、滚动边界和备用屏幕。`render()` 返回文本行、按字节索引的高亮范围，以及行 ID 到缓冲区行号的映射。
- `protocol.lua`：处理本地查询、模式协商、调色板/剪贴板行为和私有字符串分发。支持键盘消歧、全键报告和关联文本（掩码 25），不宣称支持尚未实现的按键释放/替代键标志。OSC52 读取须显式授权。
- `graphics.lua`：管理宿主图片 ID 命名空间、图片尺寸、缓冲后的原子分块上传、本地能力应答、放置生命周期、逐视图像素裁剪和宿主响应路由。读取文件元数据前以非阻塞方式打开并验证同一描述符的文件类型，防止 FIFO/设备路径阻塞界面。默认上传缓冲上限 64MB，关闭时释放所属宿主资源。
- `input.lua`、`render.lua`、`tty.lua`：分别负责原生 `on_input` 字节编码/粘贴/鼠标、内部终端通道显示及图形绘制、Linux 单元格和像素窗口尺寸 ioctl。

## 集成约定

控制器管理原始 `jobstart({pty=true})` 回调，并另建 `nvim_open_term` 通道。普通 Lua 屏幕操作镜像到内部通道，不直接修改终端缓冲区文本；嵌套屏幕调用不能重复镜像。任务回调以列表边界表示真实换行，以字符串内换行表示 NUL；应先还原各段，再拼接。引导 shell 发出私有就绪 DCS，等候 Lua 回传一行，像素尺寸安装完成后才执行真正命令。

图形能力探测必须在 DA 响应之前本地回复：icat 收到 DA 即结束探测，terminal-browser 也有较短的图形查询期限。不得把子进程键盘/备用屏幕模式转发到 Neovim 外层 TTY。普通光标、鼠标、备用屏幕模式仅镜像到内部视图。Kitty 键盘协商保留在 Lua，原生输入适配器将基础编码转换为子程序协商的格式。像素鼠标模式同样在 Lua 中处理，将原生 SGR 单元格坐标转换成子程序像素坐标。只有具有宿主效果的字符串协议通过 `nvim_ui_send` 委托给外层终端。

跨会话的完整图形上传必须原子提交。续包没有独立图片 ID，可能仅含 `m`/`q`（动画帧还可含 `a=f`），不要添加放置元数据。先刷新文字单元格，再绘制图片。图片绑定稳定网格行 ID，而非当前焦点窗口。部分可见图片裁剪时保留原始源尺寸。

即使没有新子进程输出，原生界面重绘（包括进入/离开终端模式）也可能擦除宿主图片。装饰提供器在 Neovim 刷新后调度仅图形重绘，不能写终端通道或递归触发重绘。原点模式下光标同步和 CPR 使用相对滚动边界的行号。原生 ESC、Alt+[、Alt+O 歧义前缀采用 30ms 输入超时。内部终端不能可靠应用 OSC4 调色板变更，因此按 Lua 调色板将 SGR 转为真彩色。

浏览器刷新前不能删除可见放置。复用每视图的放置 ID，用 `p=` 原位替换。重新上传同一图片 ID 也会使宿主放置失效：完整上传、显式删除和替换放置须等待同一次显示提交，以同步刷新模式 2026 包裹，单次写入宿主。删除先于上传；图片归属已释放时跳过其待上传数据。关闭时仍立即清理资源。动画验收采样 30 个合成器画面，要求动画像素确实变化、稳定页面像素不露出 Neovim 背景，且不发生多余放置删除。

不得把虚拟/相对图片放置静默转换为普通放置。不支持的语义须保留显式错误和 TODO。本实验拒绝 `U=1`，相对放置语义和 OSC66 尺寸仍不完整。测试与运行限制见 `../AGENTS.md`。
